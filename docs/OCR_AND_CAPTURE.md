# 한국어 OCR 및 화면 캡처 동작 문서

## 1. OCR 파이프라인

```text
화면 선택
  ↓
모니터별 화면 캡처
  ↓
QPixmap → PNG bytes
  ↓
PIL Image → NumPy RGB array
  ↓
PaddleOCR detection
  ↓
한국어 recognition
  ↓
OcrLine(text, confidence, box)
  ↓
같은 줄 조각 병합 + 들여쓰기 추정
  ↓
편집 가능한 Python 코드
```

OCR은 코드 실행과 분리되어 있다. OCR 결과가 틀려도 실행 전에 편집창에서 수정할 수
있어야 한다.

## 2. 사용 모델

현재 설정은 다음과 같다.

```text
Detection:   PP-OCRv5_mobile_det
Recognition: korean_PP-OCRv5_mobile_rec
Device:      CPU
Input limit: 긴 변 1,536px
```

기존 `en_PP-OCRv5_mobile_rec`는 영어 전용 모델이라 한국어를 인식하지 못했다. 현재
한국어 모델은 한국어뿐 아니라 Python 코드에 필요한 영어와 숫자도 인식하도록 선택했다.

가중치는 Git에 커밋하지 않는다. 모델을 변경하면 다음 문서를 같이 확인한다.

- `app/core/ocr.py`의 모델 이름과 탐색 경로
- `tools/prepare_ocr_models.ps1`
- `models/README.md`
- `docs/SETUP_WINDOWS.md`

## 3. OCR 결과가 정확해지는 캡처 조건

화면 OCR은 일반 문장보다 코드 기호와 들여쓰기에 민감하다. 테스트 자료는 다음 조건에
가깝게 준비한다.

- 코드만 포함되도록 영역을 좁게 선택
- 글자가 너무 작지 않게 확대
- 배경과 글자의 대비가 큰 화면 사용
- `>=`, `:`, `()`, 따옴표, `_`를 포함한 코드로 테스트
- `if`, `for`, 함수처럼 들여쓰기가 필요한 코드 포함
- 판서, 마우스 커서, PDF 페이지 번호가 선택 영역에 섞이지 않게 함
- OCR 직후 편집창에서 들여쓰기와 기호를 확인

OCR이 완전히 원본을 복원한다고 가정하지 않는다. 편집창이 최종 코드의 기준이다.

## 4. 지연 시간 정책

모델은 앱 시작 직후 `OcrWorker`에서 예열한다. 사용자가 선택 후 OCR을 누르는 시점에는
모델 초기화가 다시 일어나지 않도록 한다.

- 일반 코드 영역은 개발 PC에서 약 1.1초 수준으로 측정
- 3840×2160 원본은 긴 변을 1,536px로 줄여 약 2.6~2.7초 수준으로 측정
- 실제 시간은 노트북 CPU, 화면 배율, 글자 크기, 선택 영역에 따라 달라질 수 있음
- OCR 요청마다 모델을 새로 생성하거나 Qt 스레드 사이에서 모델을 옮기지 않음

성능을 개선할 때는 모델 예열 구조를 깨지 않는 선에서 다음 순서를 따른다.

1. 선택 영역을 불필요하게 크게 잡지 않도록 UX 개선
2. 입력 상한과 전처리 시간 측정
3. OCR 모델의 CPU 시간과 정확도 비교
4. 정확도를 훼손하지 않는 범위에서만 이미지 축소/전처리 조정

## 5. 듀얼모니터 좌표 처리

### 현재 방식

`SelectionOverlay`는 연결된 모든 모니터의 `QScreen.geometry()`를 합쳐 가상 데스크톱
전체를 덮는다. 사용자가 드래그를 시작하면 시작 지점의 모니터를 기록하고, 현재 선택
사각형을 그 모니터 안으로 제한한다.

`capture_screen_rect`는 전역 선택 사각형을 모든 화면과 교차시켜 각 화면의 영역을
따로 캡처한다. Windows의 `QScreen.grabWindow`에는 화면별 로컬 좌표가 필요하므로:

```text
로컬 x = 선택 영역 x - 해당 모니터 geometry.x
로컬 y = 선택 영역 y - 해당 모니터 geometry.y
```

로 계산한다. 모니터가 왼쪽에 배치되어 음수 전역 좌표를 갖거나, 모니터별 DPI 배율이
다른 경우에도 결과를 합성할 수 있게 했다.

### 왜 한 모니터로 제한하는가

Python 코드 한 조각은 한 모니터 안에서 선택하는 것이 일반적이다. 모니터 사이를
가로지르는 드래그를 허용하면 서로 다른 원점과 DPI가 섞이고, OCR에 빈 영역이나
잘못된 크기의 이미지가 들어갈 수 있다. 따라서 시작 모니터 밖으로 드래그하면
경계에서 선택을 멈춘다.

### 캡처 전 오버레이 제거

선택을 끝내면 오버레이를 숨긴 뒤 약간의 이벤트 루프 시간을 주고 캡처한다. 이 시간은
선택 테두리나 안내창이 원본 PDF/PPT 화면에 찍히는 것을 줄이기 위한 것이다.

## 6. 오버레이 표시 정책

선택 중 원본 화면이 보이지 않으면 사용자가 코드 영역을 정확히 지정할 수 없다.

- 전체 음영은 낮은 불투명도(현재 알파 52)
- 선택 영역은 투명하게 비워 원본을 그대로 확인
- 선택 테두리는 파란색으로 강조
- 중앙 안내 문구만 진한 색상으로 표시

음영을 다시 진하게 바꾸지 않는다. 시인성이 부족하면 먼저 테두리·크기 표시·색상
대비를 조정한다.

## 7. 실제 장비 테스트 체크리스트

### 단일 모니터

- [ ] 왼쪽 위에서 오른쪽 아래로 선택
- [ ] 오른쪽 아래에서 왼쪽 위로 역방향 선택
- [ ] 선택 영역이 원본 화면을 가리지 않음
- [ ] 미리보기에 선택 테두리/안내 문구가 포함되지 않음
- [ ] OCR 결과에서 한글 주석과 Python 기호가 편집 가능한 형태로 표시

### 듀얼모니터

- [ ] 주 모니터에서 선택
- [ ] 보조 모니터에서 선택
- [ ] 보조 모니터가 왼쪽에 있어 전역 x가 음수인 경우
- [ ] 모니터 DPI가 100%/125%처럼 다른 경우
- [ ] 한 모니터에서 시작해 다른 모니터로 넘어갈 때 범위가 경계 안에서 멈춤
- [ ] 두 모니터 모두 미리보기와 OCR 결과가 같은 위치를 가리킴

### 터치/전자칠판

- [ ] 한 손가락으로 드래그했을 때 마우스 드래그처럼 선택됨
- [ ] 버튼을 한 번 터치했을 때 클릭으로 동작
- [ ] 코드 편집창에서 커서 탭과 키보드 입력이 가능
- [ ] 터치가 포인터 이동만 만들고 버튼 누름/뗌을 만들지 않는지 확인
- [ ] 필기 인식이 아니라 터치-마우스 입력 테스트라는 점을 구분

## 8. 문제별 원인과 대응

| 증상 | 가능 원인 | 대응 |
|---|---|---|
| 한국어가 전부 누락 | 영어 모델 사용 또는 한국어 모델 미설치 | `korean_PP-OCRv5_mobile_rec` 확인 |
| 선택 화면이 너무 어두움 | 오버레이 알파 변경 | `SelectionOverlay.paintEvent`의 알파 확인 |
| 보조 모니터에서 위치가 어긋남 | 모니터 로컬 원점/DPI 문제 | `capture_screen_rect`와 실제 `QScreen.geometry()` 로그 확인 |
| 선택 영역이 다른 모니터까지 감 | 시작 모니터 제한 로직 누락 | `_selection_screen`과 clamp 로직 확인 |
| OCR에 안내창이 찍힘 | 오버레이 숨김 직후 캡처 | `main.py`의 지연 캡처 흐름 확인 |
| OCR이 느림 | 큰 영역, 예열 미완료, 모델 재생성 | 입력 크기와 `OcrWorker` 소유 스레드 확인 |
| 한글이 깨져 보임 | 콘솔 인코딩 또는 UI 글꼴 문제 | ASCII 출력으로 실제 문자열 확인 후 UI 글꼴 확인 |
