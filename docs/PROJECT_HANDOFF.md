# CodeTrace 프로젝트 인수인계 문서

> 다음 노트북에서 개발을 재개할 때 이 문서를 프로젝트의 현재 기억으로 사용한다.

## 1. 프로젝트 정의

### 제품 한 줄 정의

CodeTrace는 수업자료 화면에서 Python 코드를 가져와 OCR로 텍스트화하고, 사용자가
코드를 확인·수정한 뒤, 교육 목적의 제한된 실행기로 의미 있는 실행 Step과 Trace를
생성하여 실행 과정을 시각화하는 데스크톱 프로그램이다.

### 절대 바꾸면 안 되는 방향

이 프로그램은 다음 제품이 아니다.

- 모든 Python 문법을 실행하는 일반 Python 인터프리터
- PDF/PPT 파일을 직접 열고 내부 구조를 분석하는 문서 프로그램
- 인터넷 API에 코드를 보내 실행하는 온라인 서비스
- 사용자의 코드를 영구 저장하는 노트 앱
- 전자펜 손글씨를 자동으로 Python 코드로 변환하는 필기 앱

핵심 흐름은 항상 아래를 유지한다.

```text
Code → Parser → AST → Educational Executor → Trace → Visualization
```

실행기는 허용된 문법만 파싱하고 실행한다. 시각화 화면은 실행기를 직접 호출하지 않고
완성된 `ExecutionTrace`만 읽는다.

## 2. 확정된 제품 결정

| 항목 | 확정 내용 |
|---|---|
| 대상 환경 | Windows 11 데스크톱/노트북, 전자칠판 사용 가능성 고려 |
| 네트워크 | 실행 시 인터넷 없이 동작해야 함. OCR 모델은 미리 로컬에 준비 |
| 입력 자료 | 외부 PDF/PPT 뷰어에 보이는 화면을 사용자가 드래그해 캡처 |
| PDF/PPT 처리 | CodeTrace가 PDF/PPT를 열거나 파싱하지 않음 |
| 입력 장치 | 현재 구현은 Windows 마우스 이벤트 기준. 전자칠판은 터치-마우스 변환을 전제로 함 |
| 저장 | DB 없음. 코드 영역, OCR 결과, Trace는 메모리에만 존재하며 종료 시 사라짐 |
| 연속 선택 | 여러 영역을 선택한 순서대로 임시 보관하고 하나의 코드로 결합 |
| 취소 | 현재 선택 영역만 취소하고 이전 임시 영역은 유지 |
| 새로 시작 | 명시적으로 실행하며, 확인 후 모든 임시 영역과 OCR 결과를 삭제 |
| OCR | 로컬 PaddleOCR, 한국어·영어·숫자 지원 모델 사용 |
| 코드 확인 | OCR 결과는 반드시 편집창을 거치며 사용자가 실행 전에 수정 가능 |
| 실행 | 실제 Python 인터프리터 호출 금지. AST 기반 교육용 실행기 사용 |
| Step | 학습자가 상태 변화 또는 제어 흐름을 이해할 수 있는 최소 의미 단위 |
| UI | 실행 장면만 템플릿 원칙을 참고. 사용자 화면에 템플릿 라이브러리/왼쪽 토글을 노출하지 않음 |
| 시각화 | 중앙 실행 장면, 오른쪽 코드·상태 변화·출력, 아래 재생 컨트롤 |
| 전자펜 | 손글씨 인식은 현재 범위 밖. 키보드 입력과 마우스/터치-마우스 조작을 우선 |

## 3. 현재 기술 스택

- Python 3.12.x — 현재 PaddleOCR가 안정적으로 동작하는 개발 기준 버전
- PySide6 6.10.3 — Windows 데스크톱 UI, 다이얼로그, 오버레이, 이벤트 루프
- Pillow 12.1.1 — 이미지 변환 및 OCR 입력 보조
- NumPy 2.x — OCR 입력 배열 변환
- PaddleOCR 3.4.0 — 로컬 OCR 파이프라인
- PaddlePaddle 3.3.1 — CPU 추론
- Python 표준 `ast` — 코드 파싱 및 지원 문법 검증
- Git/GitHub — 소스 버전 관리

팀의 C#/WPF 경험이 없고 Python으로 핵심 로직을 빠르게 검증해야 했기 때문에 Python과
PySide6를 선택했다. 외부 PDF/PPT API나 온라인 서비스 의존성은 두지 않는다.

## 4. 현재 구현 상태

### 완료된 큰 기능

- 메인 Floating Tool과 코드 영역 마우스 드래그
- Esc를 통한 선택 취소
- 선택 영역 미리보기와 `OCR 실행 / 연속 선택 / 다시 선택`
- 연속 선택 영역의 순서 보존 및 메모리 결합
- `새로 시작` 확인창과 임시 세션 초기화
- 한국어 PP-OCRv5 모바일 인식 모델 연결
- OCR 예열과 추론을 하나의 장수명 전용 Python 스레드에서 처리
- OCR 결과 코드 편집창
- 지원 문법 파서와 AST 검증
- 교육용 실행기와 실행 제한
- 변수, 조건, 반복, 리스트, 함수/반환, 입력/출력 Trace
- Trace 기반 실행 장면, 코드 강조, 상태 변화, 출력, Step 재생
- 외부 자료 창과 시각화 창의 Windows Split View
- 한글 친화 UI 글꼴과 코드용 고정폭 글꼴 자동 선택
- 듀얼모니터 가상 좌표, 모니터별 로컬 캡처, 혼합 DPI를 고려한 캡처
- 바탕화면 `CodeTrace.exe` 런처

### 현재 활성 시각화 장면

현재 Trace에 실제 근거가 있을 때만 다음 장면이 활성화된다.

| 번호 | 키 | 활성 조건 |
|---:|---|---|
| 01 | `values` | 대입, 식, 입출력 등 변수 상태 정보 |
| 02 | `branch` | `if/elif/else` 조건 Trace |
| 03 | `loop` | `for/while` 반복 Trace |
| 04 | `array` | 리스트 변경 또는 리스트 상태 |
| 15 | `recursion` | 함수 호출/반환 정보 |

16개 템플릿 메타데이터는 `app/ui/template_library.py`에 있지만, 05~14와 16은 아직
실제 Executor Trace 계약이 없으므로 사용자에게 선택 메뉴로 노출하지 않는다. 설계
예시의 숫자나 값은 실행 결과로 임의 표시하지 않는다.

## 5. 사용 흐름과 상태

```text
IDLE
  ↓ 화면에서 코드 영역 드래그
SELECTING
  ↓ 선택 완료
REVIEWING
  ├─ 다시 선택 → IDLE
  ├─ 연속 선택 → OCR → IDLE (임시 영역 유지)
  └─ OCR 실행 → OCR → EDITING
                         ↓ 취소
                       IDLE
                         ↓ 실행
                       RUNNING
                         ↓
                    VISUALIZING
```

앱 시작 후 OCR 모델 예열 중에는 화면 선택 버튼이 잠시 비활성화된다. 직접 코드 입력은
OCR 준비와 관계없이 사용할 수 있다.

## 6. 다음 노트북에서 가장 먼저 할 일

1. 저장소를 `C:\CodeTrace`처럼 가능하면 ASCII 경로에 clone한다.
2. Python 3.12 가상환경을 만들고 `requirements.txt`를 설치한다.
3. OCR 모델 두 개를 `C:\Temp\CodeTrace\models`에 준비한다.
4. `python -m unittest discover -s tests -v`를 실행한다.
5. `python -m app.main`으로 직접 실행한다.
6. 외부 PDF/PPT를 열고 화면 선택 → 미리보기 → OCR → 코드 편집 → 실행을 확인한다.
7. 듀얼모니터와 가능하면 터치 장치에서 드래그 범위와 캡처를 확인한다.
8. 변경 전에 이 문서와 [DEVELOPMENT.md](DEVELOPMENT.md)의 다음 작업 목록을 읽는다.

상세 설치 절차는 [SETUP_WINDOWS.md](SETUP_WINDOWS.md), OCR/모니터 점검은
[OCR_AND_CAPTURE.md](OCR_AND_CAPTURE.md)를 따른다.

## 7. 현재 한계와 아직 검증하지 못한 것

- 실제 전자칠판 하드웨어는 아직 연결해 테스트하지 못했다. Windows가 터치/펜을 마우스
  클릭·드래그로 전달하는지에 따라 결과가 달라질 수 있다.
- 전자펜 손글씨 인식은 구현하지 않았다. 편집은 키보드 또는 화면 키보드 중심이다.
- OCR은 캡처 품질, 글자 크기, 대비, 들여쓰기, 기호에 영향을 받는다. OCR 결과는 편집창에서 확인해야 한다.
- 한국어 모델 가중치는 Git에 넣지 않는다. 현재 개발 PC에서는 `C:\Temp\CodeTrace\models`에 준비되어 있다.
- 전체 Python 문법, import, 파일 I/O, class, 재귀 등은 지원 대상이 아니다. 재귀는 설계상
  함수 장면을 위해 자리를 확보했지만 현재 Executor에서 제한될 수 있다.
- 실제 전자칠판, 다양한 DPI 배율, 모니터 배치(왼쪽/오른쪽/위/아래)는 장비를 확보한 뒤 추가 검증해야 한다.

## 8. 절대 지켜야 하는 개발 원칙

1. `exec`, `eval`, `subprocess`로 사용자 코드를 실행하지 않는다.
2. 지원 문법을 먼저 정의하고 Parser/AST/Executor를 확장한다.
3. Step을 토큰 단위가 아니라 교육적으로 의미 있는 상태 변화 단위로 기록한다.
4. Visualization이 Executor나 Parser를 직접 실행하지 않게 한다.
5. Trace에 없는 값, 화면 설계 예시의 fixture 값, 추정한 자료구조 상태를 만들어 표시하지 않는다.
6. OCR 결과를 사용자가 고칠 수 있는 단계를 없애지 않는다.
7. OCR 모델과 경로는 오프라인을 전제로 한다.
8. 새 기능을 추가하면 단위 테스트와 이 문서를 함께 갱신한다.
